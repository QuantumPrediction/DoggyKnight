# 在戰鬥和戰報認出連攜

在[網頁試玩版](https://doggy-knight-playtest.quantumprediction.chatgpt.site/)選法師。升級遇到「彗星印」和「連雷符」時各選一次，把敵人引到星的落點附近。落星後追加的雷打中另一名敵人，會閃出帶電的星，過關戰報也會記下一次「落星引雷」。

## 前後畫面

控制組為草稿 #36 的 `bc73d06d965cadd49f552ec6f53c50cc1a271629`。Linux X11、Mesa llvmpipe、Godot 4.7.2 Compatibility 實際繪製 360×640。兩次從空存檔進入同一路線，按物理 tick 配對。五張的關卡、已學把戲、玩家位置都相同。擷取器僅在已結束的 1-4 戰報暫緩按「繼續」，讓星章和數字播完。最終畫面為實際渲染的無損 WebP，逐張回讀核對 RGB。

## 路線及驗證

法師優先選新戰技，弓箭手優先選既有路線。兩者各自從空存檔完成六章 36 關、零倒下，分別有 29 與 11 關出現實際連攜。每路的 294 筆里程碑與 #36 逐欄比較。所有關卡的命中結果所反映的擊倒、受傷、戰鬥秒數、升級、選牌、存檔與按鈕幾何都相符。片尾進入和離開的 tick 有變，法師各晚 219 tick，弓箭手各早 14 tick。兩份完成存檔重啟後 SHA-256 與控制組完全相同。[完整對照與差異](runs/comparison.json) · [法師全程](runs/mage7-techniques.jsonl) · [弓手全程](runs/archer19-route.jsonl)

完整測試 1,044/1,044，戰技與結算專項 14/14，損壞測試檔 0。專項包含石化石像鬼擋下追加一擊、致命一擊、敵人離開星擊落點、一星擊中兩敵、同場復活、換關及模擬瀏海後的章末雙按鈕。首次完整測試發現空戰報多了一個欄位，已將新欄位改為有實際連攜才附加，沿用舊資料合約。兩次 300 秒測試執行逾時，最終在 650 秒上限內完整通過。新素材初次匯入曾在貼圖就緒前報錯，第二次匯入通過。第一次擷取靜止戰報時有測試腳本型別錯誤，明確指定布林型別後重播成功。離場時引擎仍報資源未釋放。歷史失敗種子繼續保存在先前的驗證中。

正式 Web PCK 已用相同 Godot 讀回，核對 36 關、連攜圖集及戰報翻譯。瀏覽器自檢通過 WASM 編譯、所有資料分片核對。本次雲端 Chromium 缺少 WebGL 2，遊戲操作及畫面驗證來自 Linux 原生。[封包指紋](web.json)

## 重跑及下一步

使用 [六章路線指令](../six-episode-campaign/README.md)，法師用 `--class=mage --seed=7 --route=0 --build=techniques`，弓手用 `--class=archer --seed=19 --route=1 --build=route`。每路指定新的 `XDG_DATA_HOME` 與戰報路徑。畫面擷取使用相同法師路線、`tests/integration/pair_impact_gallery.tscn`、X11、360×640 與獨立的 `ART_CAPTURE_DIR`。控制組只複製該測試場景及腳本，額外設定 `PAIR_CAPTURE_TICKS` 指向候選畫面的原始 `frames.json`，或直接使用已保存的 [comparison.json](frames/comparison.json)。

下次無提示試玩保留首輪和重試。先記玩家是否真的令追加招式命中、第一個注意到的畫面，以及讀完戰報後如何選擇下一張牌。目標玩家仍為 0，手機尺寸上辨認印記、幀時間、留存與外部品質評核仍待驗收。整體暫評維持 6–6.5/10。
