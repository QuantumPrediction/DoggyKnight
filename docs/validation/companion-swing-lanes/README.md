兩個案例在出招時都在該扇形外，目標是同伴。原操作在最後一次進入時，身上覆蓋的有效預警由一個增至兩個。神射在進入前速度約 10.2 px/s、方向近乎未變；遊騎約 133.7 px/s、轉向約 13.6 度。這是舊原路徑的測量，不是玩家為何轉向的解釋。

兩份新跑的完整戰報及兩份逐物理幀記錄與 #19 對照逐位元組相同。12 條介入使用同樣的已記錄前綴，保留同一出手的結算時間、原點、方向。介入後至結算幀結束，11 條完全無傷、在扇形外且沒有翻滾或無敵：4 條為放開輸入、7 條為側走。神射後段的左側路線實際仍中了所選揮擊 5 傷害。鬆開只把輸入設為零，角色仍經引擎正常減速，並非瞬間停住。固定左右方向只相對該扇形，不指定玩家的畫面左右。

## 其他命中有多相似

原來 23 次「出招時在外，最後受揮擊傷害」全部來自向同伴出手的揮擊。進入前一幀，有 18/23 次已被至少一個**其他**有效預警覆蓋；22 次有可比較的進入時角色物理更新後引擎狀態，其中 16 次同時被其他預警覆蓋。剩下的一次以結算前碰撞判定記錄進入，且沒有同一時刻其他預警的可比分解，不能拿結算後的觀測補算。23 次最後進入時距命中中位數為 14 幀，5 次只餘 0–3 幀。整個預警期間的最大重疊、進入當幀重疊與玩家實際看到的畫面是三個不同量。這些全是單一 seed 下的原路徑，重試不當作獨立玩家。

另有 13 次起初在外、結算時在內、未被該揮擊扣血的原路徑，其中 11 次同樣曾有兩個或以上重疊。單憑重疊不能判斷是哪個動作引致受傷，或畫面是否難讀。

兩個選定攻擊的預警在其起手幀就符合正式顯示條件（各為關卡觀測第 4961 和 366 幀）。本機僅以 headless 重播，**沒有量到真正畫出的第一張預警畫面**，更不能斷定玩家辨識、裝置延遲或遊戲已更好玩。下一輪先在實際渲染環境重播相同視角，逐格檢查起手、進入前及進入當幀：若場景或另一個預警顯著蓋住扇形邊界，只做一個邊界對比候選再比對。保留傷害與預警時長，另用無提示真人試玩問玩家看見甚麼、為何選那條路。既有原生崩潰、長局及實機驗收仍開放。
