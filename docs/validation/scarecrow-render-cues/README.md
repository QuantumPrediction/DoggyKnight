## 畫面與走位怎樣對上

- **神射：** t4960→4961，扇形外緣在左側戰術面板上方出現一段鮭紅色線；其他曲線跟角色及特效重疊。t4989–4990，戰術面板矩形約與外框 33.84/196.35 像素（17.2%）重合。進入附近角色中心至外框由 12.04 降至 11.86 像素，中心仍在扇形外，但 12 像素半徑的角色已碰到同一正式攻擊多邊形。介面由「預警內，先移開」改為「預警重疊，移開」。
- **遊騎：** t365→366，戰術面板與護陣按鈕之間、角色旁及較低位置可辨認兩段鮭紅外緣，但看不到完整方向。t374–375 時角色中心至扇形外框由 14.14 降至 10.27 像素（同為 12 像素碰撞半徑），左側戰術面板覆蓋原路徑上角色位置。護陣按鈕矩形和約 79.18/196.35 像素（40.3%）的外框重合。反擊成功教學位於底部、不直接與這個扇形外框相交；它出現時，既有版面把護陣按鈕和戰術面板上推 64 畫面像素。介面同樣由一項預警提示變為重疊提示。
- 上述比例是以實際 viewport 座標計算外框的線段與版面矩形重合長度，不是「看不見百分比」。矩形可半透明，角色、特效及文字未納入該比例。前後兩張的具體畫素檢查與矩形見 [畫面測量](observations.json)；有露出的鮭紅邊段，不等於從該畫面能辨認完整扇形、注意到第二個預警，或看懂安全路線。
- [#20 的成對介入](../companion-swing-lanes/README.md) 證明指定輸入避開了傷害，不是本輪實際錄到有人改走那條路。左右指相對扇形的測試方向，不是畫面左右。把測得終點投影到原畫的版面，遊騎其中一條無傷退路的終點落在教學面板下方，另一條則在下方介面之外。這只顯示版面淨空問題，不能據此推斷安全路線容易看見、原操作者一定辨認不到，或兩色對比是受擊原因。

## 不改邊線，先驗證教學提示放在哪裡

增加地面外框對比不能解決被角色或 HUD 蓋住的線段，故這一輪沒有畫面候選、A/B 或平衡修改。下一輪只登記一個候選：附近有攻擊警示時暫緩非必要的「反擊成功」教學提示，有安全空檔再補出，定義有效期限及提示優先級；不要隱藏即時警示、壓縮觸控熱區、或讓可操作按鈕在危險時移動。不要把「玩家已踏進扇形」當成唯一觸發條件，也不要因此永久隱藏教學。繼續用本輪配對，另加原位無衝突時正常顯示的對照，量度外框、腳下與離開空間的淨空；不先假定能解決同伴按鈕與角色遮擋。真人辨識／重玩、實際 Windows／手機／手把操作、音訊聆聽、長局和原生崩潰根因仍未驗證；本輪不改整體暫評，也不是 9/10 認證。

## 重跑與資料

在包含本工具的 Git checkout 根目錄，用開著視窗的 Linux 桌面終端執行（Python 3.11+、Git、相同的 Godot）。`--out` 須為新目錄，執行期間不要讓遊戲失焦。輸出會使用獨立測試存檔；一般 headless 拒絕當作畫面。兩組原政策達倒下上限，故各 Godot 退出碼 1 是封存的預期結果；整個驗證器只有在來源與各項對照通過才正常退出。

```sh
python3 -B tools/capture_scarecrow_cues.py --out /tmp/doggy-live-cue-replay
TEST_TIMEOUT=900 bash tools/run_tests.sh warning_readout
TEST_TIMEOUT=900 bash tools/run_tests.sh
```
