# 正常遊戲流程中的 Godot 原生中斷

在固定 60 Hz 的一般戰鬥量測批次，兩個遊戲程序收到 SIGSEGV，沒有寫出最後的關卡戰報。兩份文字檔是程序原始標準輸出與錯誤輸出。中斷前最後一個遊戲事件未落盤，無法定位關卡或物件。所有重跑使用不同目錄與新存檔。

| 試次 | 當次狀態 | 同一輸入另一次依序重跑 | 在 #33 另一次依序重跑 |
| --- | --- | --- | --- |
| 法師，種子 7，借盾、不操作盾，首版出場次序 | SIGSEGV，無戰報 | 通過 1-3 | 預設路線、不操作盾，通過 1-3 |
| 弓手，種子 7，預設不借、跟隨護陣指引 | SIGSEGV，無戰報 | 通過 1-3 | 預設路線、跟隨護陣指引，通過 1-3 |

這些程序使用同一個官方 Linux x86-64 Godot 4.7.2 stable，revision `ed1daf0bf001b61586d9930840f2f1394092c079`。實際 ELF 大小 146414384 bytes，SHA-256 `8d106cbe6144c2dc7e881d61d2429c1a8a76e6b22ef48bd5e48dcf934953f71e`。檔案已剝除符號，`readelf -n` 只顯示 Linux 5.15 GNU ABI tag，沒有 GNU build ID。兩份原始堆疊都記到同一組 Godot 相對位移。執行緒異常訊息和訊號處理堆疊不足以定位根因。

下一個可區分成因的證據是同一 revision、帶符號建置在正常遊戲時再次中斷的完整堆疊及執行緒狀態，另存新二進檔的 SHA-256 與 build ID（若有）。原始位移僅適用這次指紋所屬檔案。
