# v2.1 整合約定

- 提出:整合工作階段,2026-11-15(Phase 0 PR 中提出的四項補充,加上接線需要的約定)
- 狀態:已完成(擁有人授權整合工作階段自行決定並推進)

## 要改甚麼

1. EventBus 新增 `exp_collected(amount: int)`(A 線發出)與 `ultimate_requested()`(C 線發出)。
2. `LevelData` 新增 `companions: Array[StringName]`、`background: PackedScene`。
3. 資料的 `display_name`、`description` 存翻譯鍵;文字放在共用的 `i18n/strings.csv`,專案語系固定為 `zh_TW`。
4. 金毛基準數值由 `core/data/` 移到 A 線的 `data/player/goldie_base_stats.tres`。
5. 戰鬥場地合約新增 `spawn_companion()`、`set_background()`、`get_player()`。
6. 新增 `core/layout.gd`(戰鬥區與起點位置)、`Sfx` 音效 Autoload(C 線擁有,先放初版)、特效與背景的佔位資源。
7. DEV_PLAN 新增 4.9「整合約定」:數值由誰套用、暫停方式、介面場景的方法與訊號、營地銜接、音效與特效的固定名稱。

## 為甚麼

- 第 1 項:原合約沒有「拾取經驗珠」與「按下必殺技按鈕」的訊號,A 線與 B、C 線之間接不上。
- 第 2、5 項:鬥牛犬在第 3 關加入、每關背景不同,原合約沒有地方描述。
- 第 3 項:C 線規定所有文字集中在一個檔案,資料檔直接寫文字會與此衝突。
- 第 4 項:手感調整屬 A 線,不應每次都經整合工作階段。
- 第 6、7 項:四條線同時開發,接線方式必須先定死,否則整合時要大量返工。

## 影響哪些線

四條線都要讀 DEV_PLAN 4.9。這些改動在四條線開工前完成,沒有返工。

## 給擁有人的一句話說明

先把「零件怎樣接起來」講清楚,四條線同時做也能一次拼好。

## 結果

已套用到 `core/`、`project.godot`、`docs/DEV_PLAN.md`,合約測試已更新,36 個測試全部通過。
